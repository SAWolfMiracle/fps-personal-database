## v0.6.7 多图仓库识别与人工重叠核对

- 一次多选或分批添加仓库截图，最多 8 张、总计 80 MB，每张 20 MB / 2,000 万像素。相同文件 SHA-256 自动跳过。
- 各图独立保留框选区域、行列和忽略小字设置；切换图片不清除候选。重新扫描替换当前图候选，单件框选追加；清除/移除当前图保留其他图。
- 最多 512 个候选，带来源图片与稳定编号，统一核对名称、堆叠数量和勾选。
- 同类物品跨图被勾选时，每项必须确认独立物品或关联重复候选。独立堆叠累加；重复链只计根候选一次，禁止循环、未勾选引用、跨物品引用和数量不一致。
- 跨图像素坐标相同不再误判为区域重叠；同图重叠框仍禁止同时保存。
- 批量库存快照保存图片摘要来源，不保存截图；仍跳过已有库存、获取/变动历史和重复来源，未识别物品不会清零。
- 图片、裁剪与图标匹配继续在浏览器本机处理，切换工作区清除全部图片并取消未结束的读取/扫描。
- 这是人工确认重叠的多图导入，不自动拼接滚动截图、不自动判断同名物品是否同一件，也不自动读取堆叠数字。

## v0.6.6 库存增减与校正

- 收藏卡片新增“库存变动”和“校正库存”。出售、消耗、丢失、转出减少库存；转入增加库存。数量默认 1，日期和备注选填。
- 校正输入核对后的当前总数量（必填，可为 0），保留初始快照和获取历史。之后获取继续增加库存。
- 历史按记录顺序计算，补填日期不会重排；校正前的获取记录后补修改不改变校正后的数量。
- 库存变动可编辑或撤销。撤销保留历史并标记为已撤销；依赖检查阻止任何历史时点出现负库存。编辑后的提示撤销恢复修改前版本。
- 当前数量为 0 且已有历史时显示“当前无库存”，与从未获得区分。收藏进度以当前库存计算。
- JSON 与云同步包含完整库存历史；收藏 CSV 新增记录类型、变动数量、变动前后库存、记录状态。
- 仓库图标导入跳过已有库存历史的记录，保留已校正或已用完的物品；沿用原有 RLS、冲突副本和社区统计隔离。
- 出售仅记录数量，转入/转出仅更新当前物品；不含出售收入核算或另一账号/工作区的自动转账。

## v0.6.5 同步与恢复可靠性

- 同步绑定启动时的账号与工作区代次；切换后不应用旧响应，也不继续旧上传批次。
- 首次上传期间删除会更新待删除版本，并保留 5 秒撤销窗口；云删除进行中撤销会重新上传恢复记录。
- 云端按 ID 排序，每页拉取 500 条；所有页面成功后才应用，删除队列不再截断到 1,000 条。
- JSON 导入先预览新增与跳过数量。同工作区已有 ID 不覆盖，跨工作区与旧备份创建新 ID，重置同步状态；重复副本按来源工作区与原 ID 跳过。待删除 ID 恢复为副本，保留原删除操作。
- 文件读取期间切换工作区会取消导入；存储失败不会部分更新内存。冲突副本深拷贝，获取明细互不串改。
- JSON 仍备份当前工作区的对局与收藏；不是全设备备份，不含其他工作区、草稿、删除队列及设置。
- CI 在 push / pull request 时运行 Node 回归测试；RLS、Auth 配置、社区 5 人 / 20 局门槛未调整。

## v0.6.4 仓库图标匹配实验版

- 本机图标匹配：框选区域、按网格生成候选，多格物品支持单独框选；目录模板支持四个方向。
- 结果默认不勾选，人工核对物品与数量后批量保存为库存快照，复用原有账号工作区与云同步。
- 跳过已有获取历史、非零库存与同截图重复导入；未识别的物品不会被清零。

「收藏」页提供三角洲行动收藏品目录，一键加入当前工作区，也可按 1–6 级品质筛选。全部初始未获得、目标数量 1，无获取明细。重复导入按目录物品 ID 或同游戏名称跳过已有收藏，保留自定义名称、数量、目标和获取记录。访客目录与账号工作区保持隔离；收藏仍不参与社区统计。

内置 `collection-catalog.json` 是三角洲小涛查公开收藏品图鉴的2026-10-07 核对的 27 页、534 件全分页快照，记录核对时间、来源和物品 ID；名称、等级、图片 URL 来自图鉴，已知分类参考 jiansenc/DeltaForceData 的图鉴快照。只收录名称与分类等条目事实，不复制描述或下载游戏图片。来源：https://orzice.com/v/scp_book 、https://github.com/jiansenc/DeltaForceData 。这不是官方完整性保证，新赛季可能新增。重新加载按钮读取当前网站发布的快照，不访问游戏账号。

## v0.6.1 截图识别导入

在「数据」页选择对局结算或收藏数量快照，上传 PNG/JPEG/WebP（20 MB 内），点击识别，核对字段后保存。支持中文与英文；深色截图可尝试反色。一次处理一局结算或一件物品，必要时先裁剪。

识别使用 Tesseract.js 7.0.0，在浏览器本机运行。首次使用需从 jsDelivr 下载引擎和中英文模型，不需注册账号或 API Key。图片和完整识别文字不会上传或同步；只有确认的字段和图片摘要随现有记录保存。无法识别时可手动粘贴文字、补填字段。自动提取依赖明确标签，未知或冲突字段留空；游戏实际界面可能需要人工核对。

收藏数量保存为初始快照，不冒充获取日期、来源或花费。后续获取明细叠加在快照上；收藏不会进入社区对局统计。对同一截图、同类记录进行重复导入时会提示。切换账号会清除未保存的识别内容，访客数据仍需手动合并。RLS 和社区 5 用户 / 20 局门槛未改变。

## v0.6.0 收藏簿

在“收藏”页记录任意游戏的收藏品、任务物品、皮肤、武器、装备或自定义分类。

- 物品清单：游戏、名称、分类、目标数量、可选 HTTPS 图片链接、备注。
- 获取日志：每次获取的日期、数量、来源或地图、本次总花费、备注。
- 进度由获取数量累计，自动显示未获得、已获得或已集齐；支持搜索与筛选。
- 物品和获取记录都可删除并在提示期间撤销；共用现有本地优先、账号隔离、云同步及冲突副本机制。
- JSON 备份包含全部对局与收藏；对局 CSV、收藏 CSV 分别导出。旧 JSON 不带 kind 的记录继续作为对局。
- 收藏不参与对局分析或社区统计；社区仍强制至少 5 个不同用户、20 局。

收藏以 `kind: collection` 存入现有 `fps_records.payload`，沿用原有 RLS、修订号与删除标记，无新增公开权限。获取日志随所属物品一起同步；并发修改会保留冲突副本。
